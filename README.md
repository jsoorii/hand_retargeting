# 로봇 핸드 리타게팅 — 설계 및 진행 상황

MANUS Metagloves Pro → 로봇 핸드(엄지 yaw-3R, 나머지 손가락 AA-3R, 전 관절 독립 구동)
텔레오퍼레이션 리타게팅.

---

## 1. 시스템 구조

```
MANUS Metagloves Pro
   │  raw_sensor  (글러브 소스 기준 센서 포즈, 솔버 우회)
   ▼
glove_source.py ──── JumpGate (EMF 스파이크 제거)
   │  T_dorsum_nail   ← 글러브 종속성이 여기서 끝남
   ▼
hand_retarget.py ─── 팜 프레임 변환 · 스케일 · 태스크공간 필터
   │                  엄지 우선 해결 → 달성 위치를 앵커로 손가락 블렌딩
   ▼
thumb_retarget.py ── 도달 포락선 포화 · closed-form IK · 클램프 · rate limit
   │
   ▼
q (관절 명령) + pos_error (포화 피드백)

calibration.py ───── 세션 시작 시 1회 실행,
                     scale · T_dorsum_palm · R_pad_tip · d_contact_human 산출
```

### 파일 구성

| 파일 | 역할 |
|---|---|
| `thumb_retarget.py` | 1P3R 운동학, closed-form IK, 필터, 도달 포락선 포화, 관절 제한 |
| `glove_source.py` | 글러브 비종속 소스 계층, MANUS Pro/스켈레톤/제네릭 소스, 스파이크 게이트 |
| `hand_retarget.py` | 손 전체 조율, 엄지-손가락 블렌딩, 핀치 거리 매핑 |
| `calibration.py` | 스윕 기하 피팅, Umeyama 유사변환, 검증 게이트, 세션 오케스트레이션 |

### 실행

```bash
pip install -r requirements.txt

python thumb_retarget.py    # 엄지 IK 파이프라인 셀프테스트
python glove_source.py      # 소스 계층 + 스파이크 게이트 (125Hz 글러브 / 500Hz 제어)
python hand_retarget.py     # 손 전체 블렌딩 셀프테스트
python calibration.py       # 알려진 유사변환 복원 검증
```

각 모듈의 `__main__`이 독립 셀프테스트입니다. `calibration.py`는 합성 데이터로 알려진 변환을
스케일 0.02% / 회전 0.1° / 병진 0.1mm 이내로 복원하는지 확인합니다.

## 2. 핵심 설계 결정과 근거

### 2.1 자세는 2-파라미터족이고 롤은 0-DOF

3R 축이 평행하므로

```
R(q) = Rz(q0) · Rplanar(β) · R_off,    β = q1+q2+q3
```

`{Rz(α)Rplanar(β)}`는 S²와 일대일 대응입니다. **팁의 한 축(`tip_axis_local`)은 임의 방향으로 겨눌 수 있지만, 그 축 둘레의 롤은 구조적으로 제어 불가**입니다.

→ 롤에 가중치를 주지 않습니다(ε = 0). 작은 가중치라도 주면 달성 불가능한 잔차가 위치 항과 계속 싸웁니다.

### 2.2 LM 대신 closed-form + β 스캔

```
1) q0 = atan2(py,px) − atan2(d, ρ)          # closed form
2) β를 1° 격자로 스캔
     → 손목점 계산 → 2R closed form → q3 = β − q1 − q2
3) 관절한계 · 자기충돌 통과분 중
     cost = w_o·(팁축 각도오차)² + w_r·‖q−q_prev‖²  최소 선택
```

**위치는 항상 정확히 만족**되고, 지역 최소·초기값 의존성·야코비안이 모두 없습니다. 프레임당 마이크로초 단위.

### 2.3 브랜치 연속성

| 불연속 원인 | 대응 |
|---|---|
| elbow up/down | `elbow_sign`으로 굽힘 방향만 고정 |
| β argmin 점프 | β_prev 주변 ±25° **윈도우 탐색** (전역 스캔은 첫 프레임·재engage만) |
| 미세 진동 | 현재 브랜치에 `branch_bonus` 히스테리시스 |

### 2.4 도달 포락선 포화 — 데드존 금지

하드 클리핑은 경계 밖 자세를 한 점으로 뭉개서 데드존을 만들고, 조작감을 크게 해칩니다.
그래서 tanh로 압축합니다.

```
r' = r₀ + (r_hi − r₀)·tanh((r − r₀)/(r_hi − r₀)),   r₀ = r_lo + 0.9·(r_hi − r_lo)
```

**중요 — `[r_lo, r_hi]`는 스칼라가 아니라 고도각의 함수입니다.**

3R 체인의 안쪽 경계는 "체인이 얼마나 접히는지"로 정해지고 고도각에 따라 크게 달라집니다.
초기 구현은 `r_min = 0.25·r_max`라는 대충 잡은 상수를 썼는데, 실측 결과 어떤 고도에서
진짜 하한이 **57.6mm**인 반면 그 값은 **19mm**였습니다. 그 사이 대역의 목표가 포화를
통과한 뒤 IK에서 실패해 손가락이 홀드되었고, 조작자에게는 *"한쪽 방향으로 손이 안 따라옴"* 으로
보였습니다. 테스트 기준 **1500프레임 중 865프레임 IK 실패**.

→ `build_reach_envelope()`가 관절 한계 박스를 1회 샘플링해 고도각별 `[r_lo, r_hi]`를 만듭니다.

두 가지 보조 처리:

- **방위각 소프트 포화** (`soft_saturate_yaw`) — 반경만 압축하면 yaw/AA 한계는 여전히 하드
  클램프라, 다른 축은 반응하는데 측방만 딱 멈추는 데드존이 남습니다. 방위각도 tanh로 압축해
  측방 입력이 계속 측방 출력을 만들되 점점 줄어들게 합니다.
- **2mm 안쪽 마진** — 경계에 정확히 붙이면 해집합이 측도 0이 되어 1° β 격자가 밟고 지나갑니다.
  명목상 도달 가능한 목표에서 IK가 실패하는 원인이었습니다.

수정 효과: IK 실패 865/1500 → **0/1500**, 측방 데드존 885/1499 → **19/1499**,
측방 명령 −45→+36mm에 대해 달성값 −34.3→+29.6mm 단조 추종.

### 2.5 AA 클램프 + 재투영

손가락 AA 가동범위는 ±15~20°로 자주 포화합니다. 2.4의 방위각 소프트 포화가 대부분을
흡수하지만, IK 내부에도 최종 방어선을 둡니다. 단순 클램프는 평면 솔버에 도달 불가능한 점을
넘기게 되므로, **클램프된 yaw가 실제 도달하는 평면으로 목표를 재투영**합니다.
잔여 측방 오차는 `pos_error`에 그대로 드러납니다.

> 참고: 목표가 yaw 범위 밖일 때 가장 가까운 한계로 클램프하는 것이 최적입니다.
> 점에서 평면까지의 거리가 한계를 넘어서는 방향으로 단조 증가하기 때문입니다.

### 2.6 태스크 공간 필터링

관절 공간 필터링은 β 브랜치 전환을 뭉개 이상한 중간 자세를 만듭니다.

- 위치: **One Euro** (저속 강하게, 고속 약하게)
- 회전: 측지 저역통과 `R ← R·exp(α·log(RᵀR*))`
- **JumpGate를 One-Euro 앞에** 배치 — One-Euro는 고속에서 컷오프를 올리는 필터라 스파이크를 가장 빠르게 통과시킵니다. 저역통과로는 못 막습니다.

### 2.7 글러브 데이터는 최소 가공 경로

```
센서 → [Advanced Hand Solver] → raw skeleton(21노드) → retargeted skeleton
        ↑ 우회
```

`raw_sensor`는 **글러브 소스 기준** 포즈이고 글러브 소스 모듈이 손등에 있으므로, 그 값 자체가 `T_dorsum_nail`입니다. 손등 노드 차분도 솔버도 불필요.

- `raw_sensor_orientation`(손목 방향)은 사용하지 않음 — 월드 프레임이 필요 없음
- 대가: Core의 사용자별 손 스케일링이 없음 → **자체 캘리브레이션이 필수가 됨**
- 대가: EMF 지터가 필터 앞단에 직접 노출 → JumpGate 필요

### 2.8 손가락 = 엄지와 같은 구조

AA + 평행3R은 yaw + 평행3R과 위상이 동일합니다. **동일 솔버를 코드 수정 없이 재사용**하며, 베이스 프레임만 아래로 정의하면 됩니다.

```
+z = AA(벌림) 축,  −y = 세 굴곡축,  +x = 중립 지향
```

### 2.9 엄지-손가락 블렌딩

```
w(d) = w_max / (1 + exp(k(d − d_half)))
p_target = (1−w)·p_absolute + w·(anchor + d_robot·û)
```

- **앵커 = 엄지의 `p_achieved`** (클램프·rate limit 후 FK). 명령값을 쓰면 엄지가 포화하는 순간 — 즉 핀치를 시도하는 순간 — 손가락이 엄지가 도달하지도 못한 위치를 기준으로 배치됩니다
- 멀 때는 절대 매핑(자연스러운 벌린 손), 가까울 때는 상대 매핑(핀치 기하 보존)
- 약지·소지는 `w_max`를 낮춤 — 정밀 핀치에 거의 참여하지 않는데 상대 목표를 쫓게 하면 손 자세만 왜곡

### 2.10 핀치 거리 매핑

사람의 핀치 거리는 0이 아닙니다(패드 기준 15~25mm). 로봇 패드도 두께가 있습니다.

```
d_robot = d_contact_robot + scale·max(0, d_human − d_contact_human)
```

→ **사람 접촉이 로봇 접촉에 정확히 대응**. 이 매핑 없이는 관통하거나 영구히 벌어집니다.

### 2.11 포화 피드백

클램프 후 **FK로 실제 도달 위치를 재계산**해 `pos_error`로 노출합니다. 위치 정확도가 조용히 깨지는 것을 막고, 접촉 감지 트리거로도 그대로 쓰입니다.

### 2.12 클러치

- 매핑은 **절대** (마우스식 재앵커 금지 — 사람 손과 로봇 손 자세가 어긋나면 인지 부하가 큼)
- re-engage 시 1.5초 램프, 스냅 금지
- disengage 시 마지막 `q` 유지 (파지 중 대비)
- 스트림 유실 `fault_after` 초과 시 자동 disengage

### 2.13 IK 실패 시 홀드

β 윈도우가 비면 전역 스캔으로 1회 재시도하고, 그래도 해가 없으면 **`q_prev`를 유지**합니다.
초기 구현은 `np.zeros(4)`를 반환했는데, 이는 트래킹이 가장 어려운 순간에 손이 영점 자세로
스냅한다는 뜻이었습니다.

### 2.14 캘리브레이션 — 기하 + 기능 이중 추정

`raw_sensor` 경로가 솔버를 우회하므로 Core의 사용자별 스케일링이 전혀 없습니다.
이 모듈이 **유일한** 스케일 메커니즘입니다.

| 단계 | 방법 | 산출 |
|---|---|---|
| 스윕 | 엄지 = 구 피팅, 손가락 = 평면 PCA + 원 피팅 | 관절 중심, 유효 길이 |
| 기능 자세 4종 | Umeyama 유사변환 (반사 억제) | `scale`, `T_dorsum_palm` |
| FLAT 자세 | 최소 회전 정렬 | `R_pad_tip` |
| PINCH 자세 | 5퍼센타일 | `d_contact_human` |

설계상 중요한 점 세 가지:

- **손가락에 구 피팅은 부적절합니다.** AA + 평행3R의 순수 굴곡은 평면 원호를 그리므로
  구 피팅은 조건수가 나빠집니다. 면외 산포도 오차에 포함시켜 사용자가 깨끗한 굴곡을 하지
  않으면 rms로 잡히게 했습니다.
- **3점 유사변환은 겨우 결정되는 수준**이라 디짓 하나만 틀어져도 무너집니다.
  4자세 × 5디짓 = 최대 20쌍을 모두 씁니다.
- **스케일을 두 경로로 독립 추정**해 교차검증합니다. 기하학적(`L_robot/L_human`)과
  기능적(Procrustes)이 20% 이상 어긋나면 경고 — 사용자가 자세를 잘못한 것입니다.

검증 게이트(scale 범위, Procrustes rms, 대응쌍 수) 중 하나라도 실패하면
`(None, None, report)`를 반환해 **캘리브레이션 자체를 거부**합니다. 잘못된 캘리브레이션이
조용히 세션 전체를 오염시키는 것이 가장 비싼 실패 모드입니다.

> **중요**: 센서가 손끝에 클립으로 붙는 구조라 착용할 때마다 마운트 오프셋이 달라집니다.
> 사용자당 1회가 아니라 **세션 시작마다** 실행해야 합니다.

- 클러치 트리거 방식 (키보드/버튼/페달)

- One-Euro `min_cutoff`, `beta` — raw_sensor 경로는 더 보수적으로 필요

## 6. 검증 계획

### 1차 (현재) — 엄지 위치 오차

`PositionErrorMetric`: `mean_mm`, `p95_mm`, `max_mm`, `sat_ratio`

### 2차 — 기능 지표

"오차 몇 mm"보다 기능 지표가 실질적입니다.

- 핀치 성공률 (엄지-검지, 엄지-중지)
- 물체 크기별 파지 성공률
- 사용자별 캘리브레이션 후 **첫 시도** 성공률
- 브랜치 전환 빈도 (연속성 지표)
- JumpGate 거부율 (EMF 환경 건전성 지표)

### 회귀 테스트

- 도달 불가 목표에서 발산하지 않는가
- 재engage 시 램프가 스냅으로 변하지 않는가
- 스트림 유실 → 복구 시 브랜치가 튀지 않는가

## 8. 참고

- 자세 롤은 **구조적으로** 제어 불가 — 하드웨어를 바꾸지 않는 한 개선 불가능한 항목입니다.
- 손가락 리타게팅에서 절대 매핑만 쓰면 핀치가 실패하고, 상대 매핑만 쓰면 벌린 손이 부자연스러워집니다. 거리 적응 블렌딩이 그 사이를 메웁니다.
- 결합 최적화(5개 디짓 동시 solve) 대신 디짓별 독립 IK + 블렌딩 레이어를 택했습니다. 디버깅이 훨씬 쉽고, 현재 정확도 요구에서는 충분합니다.
